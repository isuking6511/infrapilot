## Phase 1: Terraform VPC & Network

### 오늘 한 일

- Terraform 프로젝트 초기 세팅 (provider, required_version, required_providers)
- VPC (10.0.0.0/16) + DNS support/hostnames 활성화
- Subnet x2 (AZ-a: 10.0.0.0/24, AZ-b: 10.0.1.0/24)
- Internet Gateway + Route Table (0.0.0.0/0 → IGW) + Association x2
- Security Group 설계 (SSH/K3s: 내 IP만, HTTP/HTTPS: 전체, Outbound: 전체)
- EC2 t3.micro 배포 (Ubuntu 24.04, gp3 20GB) + SSH 접속 성공
- Output 설정 (public_ip, instance_id, ssh_command)
- 모듈 리팩토링 (modules/vpc, modules/security, modules/compute)

### 트러블슈팅

- `hashcorp/aws` → `hashicorp/aws` 오타 (i 빠짐)
- SG ingress rule 이름 전부 동일 → Terraform 이름은 유니크해야 함
- `cidr_ipv4`에 `aws_vpc.pilot_vpc.id` 넣음 → IP 주소를 넣어야 함
- `from_port=22, to_port=443` → 포트 하나 열 때는 둘 다 같은 값
- `-var="my_ip=x.x.x.x"` → `/32` 안 붙여서 CIDR 검증 실패
- `"var.az_a"` → 따옴표 안에 var 쓰면 문자열이 됨, 따옴표 없이 써야 함
- 서브넷 CIDR에 VPC CIDR 넣음 → 서브넷은 VPC의 부분 (다른 값)
- 모듈 간 직접 참조 불가 → output으로 값 전달해야 함

### 배운 것

- `terraform plan` = 미리보기 (staging), `apply` = 실제 적용
- `resource "타입" "이름"` — 이름은 Terraform 코드 내부용, AWS 이름은 tags
- SG는 stateful — 인바운드 허용하면 응답은 자동 허용
- NAT Gateway 없이 Public Subnet + SG로 비용 최적화 가능 (월 ₩5,000 절감)
- 모듈 = 함수 (variables = 파라미터, outputs = return값)
- `.tfstate`에 실제 값 저장 → 절대 git에 올리면 안 됨
