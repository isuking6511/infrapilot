# Ansible로 K3s 서버 자동 프로비저닝하기

## 왜 Ansible인가?

서버를 처음 세팅할 때 SSH로 접속해서 명령어를 하나씩 치는 건 딱 한 번만 하면 된다.  
두 번째부터는 **자동화**가 답이다.

Ansible은 별도의 에이전트 없이 SSH만으로 서버를 제어할 수 있어서,  
"서버에 뭔가 설치"하는 초기 프로비저닝에 특히 잘 맞는다.

---

## 목표

AWS EC2 t3.micro에 다음을 자동으로 세팅한다:

1. 필수 패키지 설치
2. Swap 1GB 설정 (RAM 부족 대응)
3. K3s 설치 및 확인

---

## Playbook 구조

```yaml
- name: infra pilot
  hosts: k3s-server
  become: true   # sudo로 실행
  tasks:
    ...
```

`become: true` 하나로 모든 task가 root 권한으로 실행된다.  
서버에 직접 sudo를 치는 것과 같은 효과다.

---

## 1단계: 필수 패키지 설치

```yaml
- name: install essential packages
  ansible.builtin.apt:
    name:
      - curl
      - git
      - htop
      - net-tools
      - jq
      - python3-pip
    state: present
    update_cache: true
```

`state: present` — 이미 설치되어 있으면 건드리지 않는다.  
`update_cache: true` — apt-get update와 동일. 최신 패키지 목록을 받아온다.

---

## 2단계: Swap 설정 (t3.micro의 핵심)

t3.micro는 RAM이 1GB뿐이다. K3s만 올려도 빠듯하다.  
Swap을 1GB 추가해서 메모리 여유를 확보한다.

```yaml
- name: Create swap file
  ansible.builtin.command: fallocate -l 1G /swapfile
  args:
    creates: /swapfile   # 이미 있으면 skip → 멱등성
```

**멱등성(Idempotency)** 이 핵심이다.  
Ansible playbook은 몇 번 실행해도 결과가 같아야 한다.  
`creates: /swapfile`이 있으면 파일이 존재할 때 task를 건너뛴다.

```yaml
- name: Set swappiness
  ansible.builtin.sysctl:
    name: vm.swappiness
    value: '10'
```

`vm.swappiness=10` — RAM이 90% 찰 때까지 swap을 최대한 쓰지 않는다.  
swap은 디스크라서 느리기 때문에, 꼭 필요할 때만 쓰도록 설정.

---

## 3단계: K3s 설치

```yaml
- name: install k3s
  ansible.builtin.shell: |
    curl -sfL https://get.k3s.io | sh -
  args:
    creates: /usr/local/bin/k3s
```

K3s는 경량 Kubernetes다. 일반 K8s는 control plane만 2GB+ 필요한데,  
K3s는 500MB 이하로 동작해서 t3.micro에도 올라간다.

`creates: /usr/local/bin/k3s` — K3s 바이너리가 이미 있으면 재설치 안 함.

---

## 4단계: 정상 동작 확인

```yaml
- name: wait for k3s to be ready
  ansible.builtin.command: k3s kubectl get nodes -o json
  register: k3s_nodes
  changed_when: false

- name: node output
  ansible.builtin.debug:
    msg: "{{k3s_nodes.stdout_lines}}"
```

`register` — task의 결과를 변수에 저장.  
`changed_when: false` — 조회 task는 "변경됨"으로 표시하지 않음. 출력 전용이라는 의미.

---

## 실행 결과

```
PLAY RECAP
k3s-server : ok=10  changed=4  unreachable=0  failed=0
```

`failed=0` — 에러 없이 완료.

---

## 배운 것

| 개념 | 의미 |
|------|------|
| `become: true` | sudo 권한으로 실행 |
| `creates:` | 파일이 있으면 skip (멱등성) |
| `changed_when: false` | 조회 전용 task 표시 |
| `register` | task 결과를 변수로 저장 |
| `vm.swappiness=10` | RAM 90% 차야 swap 사용 |
