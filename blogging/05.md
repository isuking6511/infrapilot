# [InfraPilot] AI Multi-Agent 아키텍처 설계 — 왜 Agent 5명이 협업하는가

## 카테고리: Architecture / AI

---

## 배경

AI 매매 봇은 많습니다. 대부분 **하나의 AI**가 모든 걸 합니다.

```
일반 봇: AI 1개 → 분석 + 판단 + 실행 + 모니터링
```

문제:

- AI가 실수하면 바로 손실
- 검증 없이 실행
- 한 AI에 모든 책임

InfraPilot은 다르게 접근했습니다.

```
InfraPilot: AI 5명 → 분석 / 전략 / 검증 / 집계 / 모니터링
```

실제 트레이딩 팀처럼 역할을 나눴습니다.

---

## 왜 Multi-Agent인가

### 실제 트레이딩 팀과 비교

```
사람:        리서치 팀 → 전략 팀 → 리스크 팀 → 트레이더 → 감시
InfraPilot:  Analyst  → Strategist → Risk Mgr → Aggregator → Monitor
```

각 Agent가 자기 역할만 수행하고, 다음 Agent에 **JSON으로 결과를 전달**합니다. 한 Agent가 실수해도 다음 Agent가 걸러냅니다.

### 단일 Agent vs Multi-Agent

|항목|단일 Agent|Multi-Agent|
|---|---|---|
|프롬프트|모든 역할 한 프롬프트에 (3000 토큰)|역할별 집중 프롬프트 (각 500 토큰)|
|검증|없음|Risk Manager가 거부 가능|
|디버깅|"왜 BUY 했지?" 추적 어려움|Agent별 판단 근거가 JSON으로 남음|
|확장|프롬프트 수정 = 전체 영향|Agent 하나만 수정/교체|

## Agent 5명의 역할

### 1. Analyst — 객관적 시장 분석

```
입력: OHLCV 캔들 데이터
출력: {"trend": "bullish", "strength": 0.75, "summary": "상승 추세..."}
```

매매 추천 안 합니다. **데이터 기반 팩트만** 전달합니다.

### 2. Strategist — 전략 기반 시그널 생성

```
입력: Analyst 분석 결과 + Neely 지식베이스
출력: {"signal": "BUY", "confidence": 0.8, "wave_position": "Wave 3"}
```

핵심: 초기화 시 `strategies/` 폴더의 모든 JSON/Python을 **자동으로 로드**합니다. 사용자가 매번 "이거 참고해"라고 할 필요 없이, system prompt에 지식이 자동 포함됩니다.

```python
class StrategistAgent(BaseAgent):
    def __init__(self, provider, strategies_dir="strategies/"):
        self._knowledge = self._load_json_knowledge()  # JSON 전부 자동 로드
        system_prompt = self._build_system_prompt()     # 지식을 프롬프트에 주입
        super().__init__(name="strategist", provider=provider, system_prompt=system_prompt)
```

이 방식의 장점:

- 사용자가 Neely 파동 JSON을 넣으면 → 자동 반영
- 캔들 패턴 JSON을 추가하면 → 자동 반영
- 코드 수정 없이 **파일 추가만으로 전략 확장**

### 3. Risk Manager — 거부권 보유

```
입력: Strategist 시그널
출력: {"approved": false, "risk_level": "HIGH", "veto_reason": "일일 손실 3% 초과"}
```

하드 리미트 (AI 호출 없이 즉시 거부):

- 일일 손실 3% 초과 시 당일 거래 중단
- 연속 3회 손실 시 쿨다운
- 신뢰도 0.5 미만 시그널 자동 거부

### 4. Aggregator — 섹터별 종합

```
입력: 전체 코인 분석 결과
출력: {"DeFi": {"signal": "bullish", "count": 8}, "L1": {"signal": "neutral"}}
```

개별 코인 분석을 섹터(DeFi, L1, Meme 등)별로 집계합니다.

### 5. Monitor — 성과 추적

```
입력: 과거 시그널 + 실제 가격 변동
출력: {"accuracy": 0.72, "total_signals": 100, "correct": 72}
```

"AI가 3일 전에 BUY라고 했는데, 실제로 올랐나?" 를 추적합니다. 이 데이터가 대시보드에 **AI 정확도**로 표시됩니다.

## 통신 구조

Agent 간 통신은 **Pydantic + JSON**으로 합니다.

```python
from pydantic import BaseModel, Field

class TradeSignal(BaseModel):
    symbol: str
    action: str            # BUY, SELL, HOLD
    confidence: float      # 0.0 ~ 1.0
    entry_price: float | None = None
    reasoning: str = ""
```

왜 Pydantic인가:

- 타입 자동 검증 — `confidence`에 문자열 넣으면 즉시 에러
- JSON 변환 내장 — `signal.model_dump_json()`
- IDE 자동완성 지원

```python
# AI가 JSON 출력 → Pydantic 검증 → 다음 Agent에 전달
raw_json = await provider.chat(messages=[...])
signal = TradeSignal.model_validate_json(raw_json)  # 타입 검증 자동
```

## BaseAgent 설계

모든 Agent의 공통 부모 클래스:

```python
class BaseAgent(ABC):
    def __init__(self, name: str, provider: LLMProvider, system_prompt: str):
        self.name = name
        self.provider = provider
        self.system_prompt = system_prompt

    @abstractmethod
    async def process(self, message: AgentMessage):
        ...

    async def _ask_ai(self, prompt: str) -> str:
        response = await self.provider.chat(
            messages=[{"role": "user", "content": prompt}],
            system=self.system_prompt,
        )
        return response.content
```

Provider 패턴과 같은 구조:

- `LLMProvider`를 외부에서 주입받음 (의존성 주입)
- 어떤 AI를 쓰든 Agent 코드는 동일
- `system_prompt`로 각 Agent의 역할과 지식을 정의

## 정리

|설계 결정|이유|
|---|---|
|Multi-Agent (5명)|역할 분리, 검증 체계, 디버깅 용이|
|JSON 통신|AI 생성 쉬움, Pydantic 검증, 파싱 확실|
|전략 자동 로드|파일 추가만으로 전략 확장, 코드 수정 불필요|
|Risk Manager 거부권|하드 리미트로 AI 실수 방어|
|정확도 추적|"이 AI 믿어도 되나?" 를 데이터로 증명|
