# [InfraPilot] Terraform 모듈 완전 정복 — 함수처럼 인프라 재사용하기

## 1. 들어가며

- vpc.tf 하나에 리소스 14개 → 관리 불가능
- 모듈 = 함수: input 넣으면 리소스 만들고 output 반환

## 2. 모듈이 뭔가

### Python 비유

```python
def vpc_module(vpc_cidr):        # variable = 파라미터
    vpc = create_vpc(vpc_cidr)
    return vpc.id                 # output = return

def sg_module(vpc_id):            # 다른 모듈의 output을 받아서 사용
    create_sg(vpc_id)
```

### Terraform 모듈 구조

```
modules/vpc/
├── main.tf       ← 리소스 (로직)
├── variables.tf  ← 입력값 (파라미터)
└── outputs.tf    ← 출력값 (return)
```

## 3. 리팩토링 과정

### Before: 단일 파일

- vpc.tf에 VPC, Subnet, IGW, RT, Association 전부
- 하드코딩: "10.0.0.0/16", "ap-northeast-2a"

### After: 모듈 분리

- modules/vpc/ → 네트워크 리소스
- modules/security/ → 보안 그룹
- modules/compute/ → EC2

### 하드코딩 → 변수 교체

```
"10.0.0.0/16"        → var.vpc_cidr
"10.0.0.0/24"        → var.subnet1_cidr
"ap-northeast-2a"    → var.az_a
aws_vpc.pilot_vpc.id → var.vpc_id (모듈 간 참조 불가니까)
```

## 4. 모듈 간 값 전달 (핵심)

```
루트 main.tf:
  module "vpc"      → vpc_cidr 넣어줌
  module "security" → module.vpc.vpc_id 받아서 넣어줌
  module "compute"  → module.vpc.subnet_id + module.security.sg_id

VPC 모듈:     variable로 받음 → 리소스 생성 → output으로 내보냄
Security 모듈: VPC output 받음 → SG 생성 → output으로 내보냄
Compute 모듈:  VPC + Security output 받음 → EC2 생성
```

## 5. 흔한 실수 모음

|실수|왜 안 되는지|
|---|---|
|모듈 간 직접 참조 `aws_vpc.pilot_vpc.id`|다른 폴더라 참조 불가 → output 필요|
|output 이름에 점 `modules.compute.xxx`|점 사용 불가|
|subnet output에 CIDR 값 넣기|ID가 필요한데 CIDR 문자열 반환|
|루트에서 `aws_instance.pilot_ec2.public_ip`|모듈 안 리소스 → `module.compute.xxx`로 참조|

## 6. 모듈화의 진짜 가치

- 재사용: 같은 VPC 모듈로 dev/prod 환경 생성
- 가독성: site.yaml처럼 루트 main.tf만 보면 전체 구조 파악
- 협업: 팀원별 모듈 담당 가능
- 테스트: 모듈 단위로 plan/apply 가능

## 7. Terraform Associate 시험 관점

- 모듈 source 경로 (로컬, GitHub, Terraform Registry)
- variable validation
- output 활용
- 모듈 버전 관리

## 8. 마무리

- 14개 리소스를 3개 모듈로 정리
- `terraform plan`: 동일한 14개 리소스 (구조만 변경)
- 모듈화 = 유지보수성 + 재사용성 + 가독성
