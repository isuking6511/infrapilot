# [InfraPilot] Terraform으로 AWS VPC 네트워크 설계 — 모듈화와 비용 최적화

## 1. 들어가며

- InfraPilot 프로젝트 소개 (AI 에이전트 + 인프라 자동화 오픈소스)
- 이 글에서 다루는 것: VPC 설계부터 모듈 리팩토링까지

## 2. 네트워크 설계

### VPC

- CIDR: 10.0.0.0/16 (65,536 IPs)
- /16으로 잡은 이유: 서브넷 확장 여유, AWS 권장 사이즈
- enable_dns_support, enable_dns_hostnames 활성화 (EC2에 퍼블릭 DNS 부여)

### Subnet

- public_subnet1: 10.0.0.0/24 (AZ-a)
- public_subnet2: 10.0.1.0/24 (AZ-b)
- AZ 분리 이유: 가용성 확보 (한 AZ 장애 시 다른 AZ에서 운영 가능)

### Internet Gateway + Route Table

- 서브넷이 "퍼블릭"이 되려면 3가지 필요: IGW + Route Table (0.0.0.0/0 → IGW) + Association
- IGW만 만들면 왜 안 되는지: 라우팅 규칙이 없으면 트래픽이 어디로 갈지 모름

## 3. Security Group 설계

- 최소 권한 원칙 적용
- SSH(22), K3s API(6443): 내 IP만 허용 (var.my_ip)
- HTTP(80), HTTPS(443): 전체 허용 (대시보드, webhook)
- Outbound: 전체 허용 (패키지 설치, API 호출)
- 유동 IP 대응: variable로 빼서 apply 시 주입

## 4. 비용 최적화 판단

- Private Subnet + NAT Gateway = 월 ~₩5,000 추가
- 단일 인스턴스 환경에서 NAT 비용 대비 효과 분석
- 대안: Public Subnet + Security Group으로 동일 보안 수준 확보
- 결론: NAT Gateway 제거, 월 비용 ₩0~500 달성

## 5. 모듈 리팩토링

- Before: vpc.tf 하나에 모든 리소스
- After: modules/vpc, modules/security, modules/compute

### 모듈 = 함수

- variables.tf = 파라미터 (input)
- main.tf = 로직 (리소스 생성)
- outputs.tf = return값 (output)

### 모듈 간 값 전달

- VPC output(vpc_id) → Security input(vpc_id)
- VPC output(subnet_id) → Compute input(subnet_id)
- Security output(sg_id) → Compute input(sg_id)
- 루트 main.tf가 중간에서 연결

## 6. 트러블슈팅 모음

|문제|원인|해결|
|---|---|---|
|provider 다운 실패|hashcorp → hashicorp 오타|스펠링 수정|
|SG rule 에러|이름 전부 동일|유니크한 이름 부여|
|cidr_ipv4 에러|vpc id 넣음|IP 주소 넣어야 함|
|CIDR 검증 실패|/32 안 붙임|x.x.x.x/32 형식|
|서브넷 CIDR 에러|VPC CIDR과 동일|서브넷은 VPC의 부분|
