# [InfraPilot] AI Provider 추상화 설계 — 어떤 AI든 끼워 넣을 수 있는 구조 만들기

## 카테고리: Backend / Architecture

---

## 배경

InfraPilot은 AI 에이전트들이 실시간으로 시장을 분석하는 대시보드입니다. 핵심 문제가 하나 있었습니다.

> "Claude만 쓰면 Claude API 없는 사용자는 못 쓴다. OpenAI만 쓰면 마찬가지."

오픈소스로 배포할 거라 **사용자가 본인이 가진 AI를 선택**할 수 있어야 했습니다. Claude, OpenAI, Gemini, Ollama(무료 로컬) 중 아무거나.

---

## 설계: 추상 클래스 패턴

### 문제

AI마다 호출 방식이 다릅니다.

```python
# Claude
client.messages.create(model="claude-haiku", messages=[...])

# OpenAI
client.chat.completions.create(model="gpt-4o", messages=[...])

# Ollama
httpx.post("http://localhost:11434/api/chat", json={...})

# Gemini
client.aio.models.generate_content(model="gemini-2.5-flash", contents=...)
```

이걸 쓰는 쪽(Agent)에서 매번 분기 치면 코드가 지옥이 됩니다.

```python
# 이러면 안 됨
if provider == "claude":
    response = claude_call(...)
elif provider == "openai":
    response = openai_call(...)
elif provider == "gemini":
    response = gemini_call(...)
```

### 해결: 공통 인터페이스

Python의 ABC(Abstract Base Class)로 "모든 Provider는 이 메서드가 있어야 한다"는 계약을 만들었습니다.

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass


@dataclass
class LLMResponse:
    """AI 응답 통합 포맷."""
    content: str
    model: str = ""


class LLMProvider(ABC):
    """모든 AI 프로바이더가 구현해야 하는 인터페이스."""

    @abstractmethod
    async def chat(
        self,
        messages: list[dict],
        system: str | None = None,
    ) -> LLMResponse:
        ...

    @property
    @abstractmethod
    def name(self) -> str:
        ...
```

이제 Agent 코드에서는 어떤 AI인지 신경 쓸 필요 없습니다.

```python
# Agent는 이것만 알면 됨
response = await provider.chat(messages=[{"role": "user", "content": "분석해줘"}])
print(response.content)
```

provider가 Ollama든 Claude든 Gemini든, 같은 코드로 동작합니다.

## 구현: Ollama Provider

첫 번째 구현체로 Ollama를 선택한 이유:

- **무료** (로컬 실행)
- API 키 불필요
- 바로 테스트 가능

```python
class OllamaProvider(LLMProvider):

    def __init__(self, model: str = "llama3.2:3b", base_url: str = "http://localhost:11434"):
        self._model = model
        self._base_url = base_url

    async def chat(self, messages: list[dict], system: str | None = None) -> LLMResponse:
        if system:
            messages = [{"role": "system", "content": system}, *messages]

        async with httpx.AsyncClient(timeout=120.0) as client:
            response = await client.post(
                f"{self._base_url}/api/chat",
                json={"model": self._model, "messages": messages, "stream": False, "format": "json"},
            )
            data = response.json()

        return LLMResponse(content=data["message"]["content"], model=self._model)

    @property
    def name(self) -> str:
        return "ollama"
```

`format: "json"`을 넣은 이유: Agent 간 통신을 JSON으로 하기 위해서입니다. AI가 자연어로 답하면 다음 Agent가 파싱하기 어렵지만, JSON이면 Pydantic으로 바로 검증할 수 있습니다.

## 구현: Gemini Provider

```python
class GeminiProvider(LLMProvider):

    def __init__(self, api_key: str, model: str = "gemini-2.5-flash"):
        self._client = genai.Client(api_key=api_key)
        self._model = model

    async def chat(self, messages: list[dict], system: str | None = None) -> LLMResponse:
        contents = []
        for msg in messages:
            role = "user" if msg["role"] == "user" else "model"
            contents.append(
                types.Content(role=role, parts=[types.Part.from_text(text=msg["content"])])
            )

        config_kwargs = {"response_mime_type": "application/json"}
        if system:
            config_kwargs["system_instruction"] = system
        config = types.GenerateContentConfig(**config_kwargs)

        response = await self._client.aio.models.generate_content(
            model=self._model, contents=contents, config=config,
        )
        return LLMResponse(content=response.text, model=self._model)
```

Gemini에서 주목할 점:

- `google-genai` 신규 SDK 사용 (구버전 deprecated)
- `response_mime_type: application/json`으로 JSON 응답 강제
- `**config_kwargs` 패턴으로 옵션을 유연하게 조립

## 설계 결정: 왜 kwargs 패턴인가

```python
# 하드코딩 방식 (나쁨)
config = types.GenerateContentConfig(
    response_mime_type="application/json",
    system_instruction=system,
)

# kwargs 패턴 (좋음)
config_kwargs = {"response_mime_type": "application/json"}
if system:
    config_kwargs["system_instruction"] = system
config = types.GenerateContentConfig(**config_kwargs)
```

kwargs 패턴의 장점:

- **조건부 옵션 추가가 깔끔합니다** — system이 None일 때 넣으면 에러날 수 있는데, kwargs면 조건 분기만 하면 됩니다
- **확장이 쉽습니다** — temperature, top_p 등 옵션 추가할 때 함수 시그니처를 안 바꿔도 됩니다

## Agent 간 통신: JSON vs 자연어

AI 에이전트끼리 소통할 때 JSON을 강제한 이유:

```
자연어: "음... 제가 분석해보면 BUY 시그널이 나오는데요..."
→ 다음 Agent가 파싱하려면 정규식 지옥

JSON: {"signal": "BUY", "confidence": 0.7}
→ Pydantic으로 자동 검증, 바로 다음 Agent에 전달
```

시장 데이터 저장은 Parquet이 효율적이지만 (컬럼 압축, 백테스트 속도), Agent 통신은 AI가 생성하기 쉬운 JSON이 정답입니다.

## 테스트

```python
async def main():
    provider = OllamaProvider()
    response = await provider.chat(
        messages=[{"role": "user", "content": "BTC 시장 분석해줘"}]
    )
    print(response.content)

asyncio.run(main())
```

Ollama로 로컬 테스트 성공. Gemini는 무료 티어 쿼터 제한이 있어서 피크 시간대에 503/429 에러가 발생할 수 있습니다.

## 정리

|항목|선택|이유|
|---|---|---|
|패턴|ABC 추상 클래스|Provider 교체 가능, 확장 용이|
|첫 구현|Ollama|무료, 키 불필요, 즉시 테스트|
|통신 포맷|JSON 강제|Agent 간 파싱 용이, Pydantic 검증|
|옵션 조립|kwargs|조건부 옵션, 확장성|
|API 키 관리|외부 주입|.env든 K8s Secret이든 호출자가 결정|
