## 1) DB 스키마 정의: `schema.py`

```sql
CREATE TABLE IF NOT EXISTS ohlcv (
    id          SERIAL PRIMARY KEY,
    symbol      VARCHAR(100)  NOT NULL,
    interval    VARCHAR(5)    NOT NULL,
    timestamp   BIGINT        NOT NULL,
    open        NUMERIC       NOT NULL,
    high        NUMERIC       NOT NULL,
    low         NUMERIC       NOT NULL,
    close       NUMERIC       NOT NULL,
    volume      NUMERIC       NOT NULL,
    created_at  TIMESTAMP     DEFAULT NOW(),
    UNIQUE (symbol, interval, timestamp)
);
```

### 설계 포인트

1. **캔들 자연키 보장**
   - `(symbol, interval, timestamp)` 유니크 제약으로 중복 삽입 차단

2. **정밀도 보존**
   - 가격/거래량을 `NUMERIC`으로 정의해 부동소수 오차 영향을 줄임

3. **생성 타임스탬프 분리**
   - 시장 시점(`timestamp`)과 DB 입력 시점(`created_at`)을 구분

## 2) 저장소 계층: `repository.py`

### 연결 함수

```python
def get_connection():
    return psycopg2.connect(
        host=os.environ["DB_HOST"],
        port=os.environ.get("DB_PORT", "5432"),
        dbname=os.environ["DB_NAME"],
        user=os.environ["DB_USER"],
        password=os.environ["DB_PASSWORD"],
    )
```

환경변수 기반으로 연결 파라미터를 주입받아 실행환경(Lambda/로컬)별 설정 분리가 가능해졌다.

### 초기화 함수

```python
def init_db():
    with get_connection() as conn:
        with conn.cursor() as cur:
            cur.execute(CREATE_TABLES_SQL)
        conn.commit()
```

핸들러 시작 시 테이블 생성 DDL을 보장해 초기 배포 단계에서 마이그레이션 누락 위험을 줄인다.

### 저장 함수

```python
sql = """
    INSERT INTO ohlcv (symbol, interval, timestamp, open, high, low, close, volume)
    VALUES (%s, %s, %s, %s, %s, %s, %s, %s)
    ON CONFLICT (symbol, interval, timestamp) DO NOTHING
"""
cur.executemany(sql, rows)
return cur.rowcount
```

#### 핵심 의미

- 배치 재실행/재시도 시 동일 캔들 중복 삽입을 허용하지 않음
- `rowcount`를 반환해 실제 반영 행 수를 상위 레이어에서 집계 가능

## 3) Lambda 진입점: `lambda_/handler.py`

```python
def handler(event, context):
    init_db()
    symbols = fetch_symbols()
    total_saved = 0
    for symbol in symbols:
        candles = fetch_ohlcv(symbol)
        saved = save_ohlcv(symbol, "15m", candles)
        total_saved += saved
    return {"status": "ok", "saved": total_saved}
```

### 실행 흐름

1. 테이블 초기화
2. 거래대금 기반 심볼 목록 로드
3. 심볼별 15분봉 수집
4. 중복 방지 저장
5. 누적 저장 건수 반환

4/17 이전에는 수집 코드가 "데이터 획득" 중심이었다면, 이 커밋으로 "영속 저장까지 완료하는 실행 단위"가 완성됐다.

## 4) 테스트 계층

### `tests/test_testdb.py`

- 더미 캔들 1건 저장 후 동일 데이터 재삽입 시 0건인지 확인

```python

saved_again = save_ohlcv("BTCUSDT", "15m", dummy_candles)
```

중복 방지 정책이 코드/DB 제약에서 함께 동작하는지 검증하는 테스트다.

## 정리

이번 커밋의 본질은 다음 한 줄이다.

> **Collector 출력(dict candles)을 PostgreSQL에 idempotent하게 적재하는 Lambda 경로를 확정했다.**

스키마 제약(UNIQUE), SQL 충돌 처리(`ON CONFLICT DO NOTHING`), 테스트(중복 삽입 검증)가 한 묶음으로 들어오면서 InfraPilot 데이터 파이프라인의 첫 안정판이 만들어졌다.
