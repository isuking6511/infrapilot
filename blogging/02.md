# [InfraPilot] Ansible로 K3s 클러스터 자동 구축 — t3.micro에서 Kubernetes 돌리기

## 1. 들어가며

- Terraform vs Ansible 역할 분리
    - Terraform: 인프라 생성/삭제 (서버를 만드는 도구)
    - Ansible: 서버 내부 설정 (만들어진 서버를 세팅하는 도구)
- 왜 Ansible인가: 에이전트 없음(SSH만 있으면 됨), 멱등성, YAML 기반

## 2. Ansible 프로젝트 구조

- ansible.cfg: 기본 설정 (inventory 경로, SSH 키, 유저)
- inventory/dev.yaml: 대상 서버 목록 (EC2 IP)
- site.yaml: 메인 플레이북 (실행할 작업 정의)
- `ansible all -m ping`으로 연결 테스트

## 3. 기본 패키지 설치

- ansible.builtin.apt 모듈
- state: present = "설치되어 있어야 한다" (없으면 설치, 있으면 건너뜀)
- update_cache: true = apt update 먼저 실행
- become: true = sudo 권한 필요
- 멱등성 확인: 두 번째 실행 시 changed=0

## 4. K3s vs K8s vs minikube

|항목|K8s|K3s|minikube|
|---|---|---|---|
|최소 메모리|4GB+|512MB|2GB|
|용도|프로덕션|엣지/소규모|로컬 개발|
|설치|복잡|한 줄|한 줄|
|Docker 필요|별도 설치|containerd 내장|내장|

- 선택 이유: t3.micro (1GB) 환경 → K3s만 가능

## 5. K3s 설치 자동화

- `curl -sfL https://get.k3s.io | sh -`
- shell 모듈 + `creates: /usr/local/bin/k3s` → 멱등성 확보
- `--tls-san` 옵션: 원격 kubectl 접속 시 인증서에 퍼블릭 IP 포함 필요

## 6. t3.micro 메모리 전쟁

### 문제

- 1GB RAM에서 K3s + apt update → 메모리 95%, IO Wait 82%
- SSH 접속 불가, EC2 재부팅도 안 됨

### 원인

- swap 미설정 → 메모리 부족 시 OOM

### 해결

- user_data로 EC2 부팅 시 1GB swap 자동 생성
- `#!/bin/bash` 앞 공백 주의 (공백 있으면 스크립트 미실행)
- swappiness=10 (메모리 부족할 때만 swap 사용)

### 메모리 예산

```
OS + K3s:     ~350MB
앱 (Python):  ~200MB  
Prometheus:   ~150MB
Swap:         1GB (EBS)
여유:         ~200MB
```

## 7. 트러블슈팅 모음

|문제|원인|해결|
|---|---|---|
|inventory 파싱 실패|.yml vs .yaml 확장자|ansible.cfg 경로 수정|
|apt 설치 멈춤|메모리 부족|swap 설정|
|SSH 접속 불가|EC2 메모리 풀, OOM|중지→시작, swap 추가|
|TLS timeout|K3s 초기화 중 + 메모리 부족|swap 후 재시작|
|kubeconfig 권한 에러|/etc/rancher/ root 소유|sudo cp → /tmp 경유|
|x509 인증서 에러|퍼블릭 IP 미포함|--tls-san 옵션|
