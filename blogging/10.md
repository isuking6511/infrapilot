## 1) 루트에서 모듈 체인 연결

`iac/main.tf`에서 핵심은 아래 두 블록이다.

```hcl
module "rds_security" {
  source    = "./modules/rds_security"
  vpc_id    = module.vpc.vpc_id
  ec2_sg_id = module.security.sg_id
}

module "rds" {
  source             = "./modules/rds"
  db_username        = var.db_username
  db_password        = var.db_password
  private_subnet_ids = [module.vpc.private_subnet1_id, module.vpc.private_subnet2_id]
  rds_sg_id          = module.rds_security.sg_id
}
```

### 의미

- 보안 모듈(`rds_security`)이 먼저 생성한 SG를 DB 모듈(`rds`)에 주입
- DB 서브넷은 **private subnet 2개**를 사용해 외부 노출을 차단

## 2) RDS 모듈: 인스턴스와 서브넷 그룹 분리

`iac/modules/rds/main.tf`

```hcl
resource "aws_db_subnet_group" "main" {
  name       = "infrapilot-db-subnet-group"
  subnet_ids = var.private_subnet_ids
}

resource "aws_db_instance" "main" {
  identifier        = "infrapilot-db"
  engine            = "postgres"
  engine_version    = "15"
  instance_class    = "db.t3.micro"
  allocated_storage = 20

  db_name  = "infrapilot"
  username = var.db_username
  password = var.db_password

  db_subnet_group_name   = aws_db_subnet_group.main.name
  vpc_security_group_ids = [var.rds_sg_id]
  publicly_accessible    = false
  skip_final_snapshot    = true
}
```

### 설계 포인트

1. `publicly_accessible = false`로 퍼블릭 접근 차단
2. 사용자/비밀번호를 루트 변수에서 주입해 민감정보 분리
3. SG ID를 외부 입력(`var.rds_sg_id`)으로 받아 모듈 결합도 축소

## 3) RDS 보안 모듈: SG 참조 기반 인바운드

`iac/modules/rds_security/main.tf`

```hcl
resource "aws_vpc_security_group_ingress_rule" "allow_ec2_to_postgres" {
  security_group_id            = aws_security_group.pilot_rds_sg.id
  referenced_security_group_id = var.ec2_sg_id
  from_port                    = 5432
  ip_protocol                  = "tcp"
  to_port                      = 5432
}
```

### 이 방식이 중요한 이유

- CIDR 오픈이 아니라 **EC2 SG를 가진 인스턴스만 허용**
- 추후 Lambda SG를 붙일 때도 같은 패턴으로 확장 가능

`variables.tf`에 `lambda_sg_id`가 optional(`default = null`)로 들어가 있어, 후속 Lambda 연결을 염두에 둔 인터페이스가 미리 준비됨.

## 4) VPC 모듈 확장: private subnet 명시화

`iac/modules/vpc/main.tf`에서 private subnet 1/2를 별도 리소스로 정의했고, `outputs.tf`에 아래를 노출했다.

```hcl
output "private_subnet1_id" { ... }
output "private_subnet2_id" { ... }
output "private_subnet_ids" { ... }
```

### 결과

- RDS가 퍼블릭 서브넷을 실수로 참조할 여지를 제거
- 루트에서 `private_subnet1_id`, `private_subnet2_id`를 직접 wiring 가능

## 5) 루트 변수/출력 계약 추가

### 입력

`iac/variables.tf`

```hcl
variable "db_username" { type = string }
variable "db_password" { type = string, sensitive = true }
```

### 출력

`iac/output.tf`

```hcl
output "db_endpoint" { value = module.rds.db_endpoint }
output "db_name"     { value = module.rds.db_name }
```

운영자는 Terraform 루트 출력만으로 DB 접속 endpoint/name을 확인할 수 있다.
